# 主模型选择建议

更新时间：`2026-05-13`

## 1. 先回答核心问题

当前不建议直接把 `Mamba-CLIP` 固定为唯一主模型。

原因不是它一定不好，而是现阶段证据更支持下面这个判断：

- **Mamba 系模型**已经在遥感变化检测上证明了稳定的效率与精度优势。
- **CLIP / 文本语义路线**已经证明能改善语义理解与泛化，但作为主干直接使用时，工程复杂度和适配成本更高。
- 湿地场景最难的是**伪变化抑制**与**细碎边界保留**，这两个问题分别更接近：
  - `Mamba + 局部细节增强`
  - `轻量语义先验`

因此当前最稳妥的论文路线是：

> 先把 `Mamba` 选成主干候选，再决定语义模块是否采用 `CLIP / RemoteCLIP / GeoRSCLIP / 文本提示学习`。

---

## 2. 建议的主模型筛选顺序

### 第一优先级：先做 backbone 筛选

建议依次验证：

1. `ChangeMamba`
2. `CDMamba`
3. `CD-Lamba`
4. `M-CD`

筛选标准：

- `F1`
- `IoU`
- 推理速度 / 显存占用
- 对湿地边界、小斑块、伪变化区域的可视化表现

### 第二优先级：再做语义增强筛选

建议依次比较：

1. 不加语义模块
2. 加固定 prompt 的 `CLIP / RemoteCLIP`
3. 加可学习 prompt
4. 加文本对齐损失

筛选标准：

- 是否显著降低 `False Alarms`
- 是否提高跨区域泛化
- 是否带来可解释的湿地类别迁移信息

---

## 3. 当前最推荐的三种论文主线

## 主线 A：稳妥型

**主干：`ChangeMamba`**

**增强：轻量文本语义引导**

特点：

- 工程风险最低
- 最容易和现有 baseline 衔接
- 最适合先做出稳定结果

适合论文表述：

> 在高效 Mamba 主干的基础上，引入轻量语义提示约束，提高湿地场景中的伪变化抑制能力。

## 主线 B：更像“模型创新”

**主干：`CD-Lamba` 或 `CDMamba`**

**增强：RemoteCLIP/GeoRSCLIP 语义引导**

特点：

- 更符合“模型改进型论文”的定位
- 既能讲结构创新，也能讲语义先验
- 更适合强调小斑块与复杂边界

适合论文表述：

> 在局部-全局协同状态空间建模的基础上，引入遥感领域视觉语言先验，实现高效且具语义判别能力的湿地变化检测。

## 主线 C：边界与对象增强型

**主干：`ChangeMamba / CDMamba`**

**解码：借鉴 `MaskCD` 的对象级 mask 解码**

特点：

- 更适合强调复杂边界、碎片斑块
- 如果湿地实验里边缘表现是主要短板，这条线很值得

---

## 4. 暂不建议优先投入的方向

### 4.1 直接复刻 ChangeCLIP 作为唯一主线

原因：

- 结构更重
- prompt 体系与湿地类别需要重新梳理
- 训练和调试成本较高
- 不一定比“更强的 Mamba 主干 + 轻量语义模块”更划算

### 4.2 直接做开放词汇语义变化检测

如：

- `Semantic-CD`
- `TextSCD`

这些很前沿，但更适合作为：

- 中后期增强实验
- 论文讨论与展望
- 语义模块设计参考

而不建议一开始就作为唯一主线。

---

## 5. 当前建议的实验推进顺序

1. 复现 `ChangeMamba`
2. 增加 `CDMamba` 或 `CD-Lamba`
3. 在最强 Mamba 主干上加轻量语义模块
4. 判断是否还需要引入 `MaskCD` 风格解码头
5. 最后再决定最终论文主模型名称和结构

---

## 6. 一句话结论

当前最推荐的策略不是“先定 `Mamba-CLIP` 再证明它可行”，而是：

> **先用调研和实验筛出最强的 Mamba 主干，再判断是否需要引入 CLIP/文本语义模块进行融合。**

---

## 7. 非 Mamba 候选的补充判断

为了避免主模型选择被单一路线锁死，当前建议把非 Mamba 候选分成 4 类看待。

### 7.1 可直接竞争主模型的非 Mamba 骨干

优先级最高的是：

1. `STeInFormer`
2. `ChangeViT`
3. `MaskCD`
4. `RCDT`

判断依据：

- `STeInFormer` 更像“专为 RSCD 设计的 Transformer backbone”，值得和 `ChangeMamba` 正面比较。
- `ChangeViT` 证明 plain ViT 在大尺度变化建模上有竞争力，是很强的非 Mamba 对照。
- `MaskCD` 虽然不是普通 backbone，但它在边界和对象完整性上很可能优于标准像素分类方法。
- `RCDT` 结构简洁，适合做一个“实现成本不高但比较强”的 Transformer 对照。

### 7.2 最适合与主干做融合的语义模型

优先级最高的是：

1. `ChangeCLIP`
2. `LSC-CD`
3. `TextSCD`
4. `Semantic-CD`
5. `ClearSCD`

判断依据：

- `ChangeCLIP` 最接近你原先的设想，适合作为语义模块直接参考。
- `LSC-CD` 比较轻，适合做“低成本语义增强”。
- `TextSCD` 和 `Semantic-CD` 更适合后期把任务从二值变化拓展到语义变化。
- `ClearSCD` 更适合作为“变化关系建模”参考，而不是直接照搬。

### 7.3 最适合做泛化和基础模型路线验证的模型

优先级最高的是：

1. `BAN`
2. `RoCD`
3. `AdaptVFMs-RSCD`
4. `FMT`
5. `Changen2`

判断依据：

- `BAN` 是相对稳妥的 foundation model 适配路线。
- `RoCD` 代表“冻结视觉基础模型 + 轻量解码器”的方向。
- `AdaptVFMs-RSCD` 很前沿，但工程复杂。
- `FMT` 目前更偏探索。
- `Changen2` 更适合做数据增强、预训练和零样本讨论，而不是直接当你的当前主模型。

### 7.4 当前非 Mamba 路线的最终建议

如果后续实验发现：

- `ChangeMamba` 类模型在湿地伪变化上提升有限
- 但 `ChangeCLIP / TextSCD` 类方法能明显降低误检

那么建议转为：

> **`STeInFormer / ChangeViT` 做非 Mamba 主干候选，`ChangeCLIP / LSC-CD / TextSCD` 做语义增强候选，最终以实验决定是否保留 Mamba。**

这意味着：

- `Mamba-CLIP` 只是候选融合方案之一
- `Transformer + 语义增强`
- `Mask decoder + 语义增强`
- `Foundation model adaptation + CD head`

也都应当保留为备选主线
